# 英会話練習 Web アプリ 技術検討資料

サークルの活動を補助する英会話練習アプリを、**費用ゼロ・サーバーなし・APIキーなし**で作れるかを検討した資料です。結論として作れることを確認し、実際に [../app/](../app/) に実装しました。本書はその技術的な判断根拠と、引き継ぐ人が知っておくべき制約をまとめたものです。

記載の挙動の多くは Chrome 151 を実際に起動して計測した結果ですが、ブラウザの仕様は頻繁に変わります。節ごとに確度を明示し、裏が取れなかったものは §9 に分離しています。

---

## 1. 結論: Web Speech API を使えば無料でできる

ブラウザに標準で入っている **Web Speech API** を使うと、音声認識と読み上げの両方が追加費用なしで実現できます。有料の音声APIも検討しましたが、サークルの練習用途には過剰でした。

| 項目 | 本アプリの選択 | 費用 |
|---|---|---|
| 音声認識(話した英語を文字にする) | Web Speech API の `SpeechRecognition` | 0円 |
| 読み上げ(お手本の英語を再生する) | Web Speech API の `SpeechSynthesis` | 0円 |
| 学習記録の保存 | ブラウザの `localStorage` | 0円 |
| 公開・配信 | GitHub Pages | 0円 |
| サーバー・データベース | **使わない** | 0円 |
| APIキー・アカウント登録 | **不要** | 0円 |

サーバーを持たないので、部員の代替わりで「支払いが止まってサービスが死ぬ」ことがありません。語学サークルのように運営主体が毎年入れ替わる団体では、この点が機能の多さより重要だと判断しました。

**要するに**: 追加費用ゼロ、契約ゼロ、サーバーゼロで英会話練習アプリは作れます。その代わり、後述する動作環境の制約を受け入れる必要があります。

---

## 2. 使う API は 2 つだけ

Web Speech API は名前こそ1つですが、中身は独立した2つの機能に分かれています。**この2つは別物で、対応状況も落とし穴もまったく違います。**

| | `SpeechRecognition`(音声認識) | `SpeechSynthesis`(読み上げ) |
|---|---|---|
| 何をするか | マイクの音声を文字列にする | 文字列を音声で読み上げる |
| Chrome での呼び名 | `window.webkitSpeechRecognition` | `window.speechSynthesis` |
| 処理する場所 | **Google のサーバー**(既定) | 端末内、または Google のサーバー |
| インターネット | **必須** | 端末内蔵の声なら不要 |
| 対応ブラウザ | 狭い(§3) | 広い。ほぼ全ブラウザ |
| マイク権限 | 必要 | 不要 |

読み上げは対応が広く安定しているのに対し、**音声認識は対応ブラウザが狭く、インターネット接続が必須**です。アプリの制約はほぼすべて音声認識側から来ます。

なお、音声認識は Chrome 139 以降で端末内処理(`processLocally`)にも対応しましたが、事前に約60MBの言語パックのダウンロードが必要でした(実測。確度: 高)。新歓ブースで初めて触る人に60MBのダウンロードを待たせるのは現実的でないため、本アプリでは採用していません。

**要するに**: 読み上げは安心して使えます。制約はすべて音声認識側にあると考えてください。

## 3. 動作環境の制約

ここが本アプリで最も重要な節です。**「なぜか動かない」の原因はほぼここに集約されます。**

### 3-1. ブラウザ対応

Chrome 151 での実測と MDN のブラウザ互換データによる整理です(確度: 高。ただし iOS と Safari は挙動報告ベースで確度: 中)。

| ブラウザ | 音声認識 | 備考 |
|---|---|---|
| **パソコンの Chrome** | ○ 安定 | **推奨環境** |
| Android の Chrome | △ 動くが不安定 | `continuous` が効かない。応答が返らなくなる報告あり |
| **iPhone / iPad の Chrome・Edge・Firefox** | ✕ **不可** | Apple が WKWebView で無効化しており、必ず `service-not-allowed` エラーになる |
| iPhone / iPad の Safari | △ 動くが不安定 | マイクが止まらない・結果が返らない不具合報告が多い |
| macOS の Safari | △ 14.1以降で動く | Chrome ほど安定していない |
| Firefox | ✕ 既定で不可 | 142でフラグ付き実装。既定はオフ |
| Edge(パソコン) | (要確認) | Chromium ベースだが今回未検証。§9 参照 |

本アプリは **パソコンの Chrome を推奨環境**とし、それ以外では警告または非対応画面を出す設計にしました。ただし**非対応ブラウザでも「音声なしでフレーズ集を読む」導線だけは残して**あります。教材を読むだけなら全ブラウザで動くので、来てくれた部員に何も渡さないのは損だからです。

**スマホは「非対応」ではなく「警告つきで使わせる」に倒しています。** Android の Chrome と iPhone・iPad の Safari は、実際に音声認識・読み上げが動きます。塞ぐと部員がその場で試せる機会を失うほうが損だと判断し、起動時に注意の帯を出したうえで通常どおり使わせます。Safari 以外の iOS ブラウザ(Chrome・Firefox・Edge)だけは Apple 側の制約で原理的に動かないため、そこだけ非対応画面にしています。

### 3-2. インターネット接続が必須

Chrome の音声認識は、**マイクの音声を Google のサーバーへ送って文字にしています**。MDN も明記しているとおり、既定ではオフラインで動きません(確度: 高)。

学内の Wi-Fi がプロキシで外部通信を制限している場合、`network` エラーで認識が一切できないことがあります。**部室で初めて使う前に、必ずその場のネットワークで動作確認してください。**

### 3-3. `file://` で開くと音声認識が使えないことがある

`index.html` をダブルクリックして開いた場合(`file://`)、実測では `isSecureContext` が `true` になり音声認識自体は動作しました。ただしこれは権限を自動許可したヘッドレス Chrome での計測で、**通常起動の Chrome がマイク権限のダイアログを正しく出すかは未検証**です(確度: 中)。

そのため本アプリは **GitHub Pages(https)での公開を正規の配信方法**とし、`file://` で開かれた場合は警告帯を出したうえで、教材閲覧・読み上げ・採点ロジックは動くようにしてあります。

この判断のために、アプリの JavaScript は **`<script type="module">` を使わず、素の `<script src>`(classic script)で分割**しています。`file://` で CORS に阻まれるのは ES Modules と `fetch()` だけで、classic script の外部読み込みは通るためです(実測。確度: 高)。**この構成は意図的なものなので、モダンだからという理由で ES Modules に書き換えないでください。**

**要するに**: 「パソコンの Chrome で、インターネットに繋いで、GitHub Pages の URL を開く」が唯一の推奨手順です。部員にはこの URL だけを配ってください。

## 4. 有料サービスと比べて何を諦めたか

無料である以上、諦めたものがあります。**最も重要なのは「発音の良し悪しを評価できない」ことです。**

| 用途 | 無料の選択肢(採用) | 有料の選択肢 | 有料にすると何が変わるか |
|---|---|---|---|
| 音声認識 | Web Speech API | OpenAI Whisper、Google Cloud Speech-to-Text | オフライン動作、精度向上、ブラウザ非依存 |
| 読み上げ | Web Speech API | Google Cloud TTS、Amazon Polly、ElevenLabs | 自然な発音、声の選択肢 |
| **発音評価** | **できない** | Azure Pronunciation Assessment など | 音素単位で「th が言えていない」を直接判定できる |
| 会話練習 | (未実装) | Claude API 等と組み合わせる | AI と自由に英会話できる |

Web Speech API が返すのは**認識された文字列だけ**で、音素ごとのスコアは取れません。つまりこのアプリが測れるのは「**Google の認識器に伝わったか**」であって、「発音が正しいか」ではありません。

これは弱点ですが、隠すよりも設計思想として引き受けました。アプリの UI・README・コードコメントすべてで **「発音採点」という言葉を使わず「伝わり度」「◯語中◯語が伝わりました」と表現する**ルールを設けています。機械に伝わる発音は人間にもだいたい伝わるので、初級者の練習指標としては十分に機能します。

**要するに**: 発音矯正アプリは無料では作れません。作れるのは「**英語を声に出す回数を増やす装置**」と「**自分が通じにくい語の発見器**」です。この位置づけを部員にも正直に伝えてください。

## 5. 「伝わり度」をどう計算しているか

お手本の英文と、認識された文字列を比較して採点します。処理は3段階です。

### 5-1. 正規化 — 何を「同じ」とみなすか

認識結果は大文字小文字も句読点も揺れるので、比較前に揃えます。ただし**揃えすぎると採点が意味を失います**。

| 揃える | 揃えない |
|---|---|
| 大文字小文字、句読点、余分な空白 | **語順** |
| 縮約形(`don't` = `do not`) | **単数複数**(`book` ≠ `books`) |
| 数字と数詞(`2` = `two`) | **時制**(`go` ≠ `went`) |
| 英米綴り(`colour` = `color`) | **冠詞の有無**(`a book` ≠ `book`) |
| つなぎ語(`um`, `uh`)の除去 | 語幹への還元(ステミング) |
| 同音異義語(`their` = `there`) | |

語順を無視すると `I ate an apple` と `Apple eat I` が同点になってしまいます。リピート練習の目的は「お手本の文をそのまま言えること」なので、右列は意図的に区別しています。

### 5-2. 単語の対応付け

正規化した単語列どうしを**単語単位のレーベンシュタイン距離**で対応付け、各語を「正解 / 惜しい / 誤り / 抜け / 余分」の5種に分類します。綴りの近さを置換コストに混ぜることで、似た語どうしが優先的に対を作るようにしています。

### 5-3. 点数化

素の単語誤り率(WER)はそのまま使っていません。次の調整を入れています。

- **機能語(`a` `the` `of` など)の重みを 0.6 に下げる**。認識器が最も落としやすく、落ちても意味は通じるため
- **綴りが近い誤りには部分点**を与える。`economics` → `economic` を全滅扱いにしない
- **余分な語のペナルティは抜けの半分**、かつ合計25%で頭打ち。言い直しや認識器の暴走で0点になる事故を防ぐため
- **内容語に誤りがあれば、90点以上でも最高評価には昇格させない**。「`a` が抜けただけの90点」と「`right` を `light` と言った91点」を同じ評価にしないため
- 1フレーズ **3回中2回**で合格。1回の誤認識で理不尽に落とされず、まぐれ1回でも通らず、必然的に3回声に出すことになります

さらに、**「うまく拾えなかった」ボタンで、その回を記録から除外できる**ようにしました。周りがうるさかった、マイクが遠かったといった理由で不当に低い点が付いたとき、ユーザーに拒否権がないと「機械が悪いのか自分が悪いのか分からない」状態になり、練習が続きません。

**要するに**: 1回の点数は環境ノイズを多く含むので当てにしないでください。信頼できるのは **20回分ぐらい溜まったときの「通じにくい語ランキング」** です。これがこのアプリの一番の出力です。

## 6. 実装上の落とし穴

Web Speech API は「動くコードを書く」のは簡単ですが、「壊れないコードを書く」のは難しい API です。調査で35項目の落とし穴を洗い出し、すべて実装に反映しました。特に重要なものだけ挙げます。

| 落とし穴 | 起きること | 対策 |
|---|---|---|
| **読み上げの声を自分のマイクが拾う** | 何も言っていないのに満点が出る | 読み上げと認識が同時に動く経路をコード上に作らない。読み上げ終了後 400ms 待ってから録音開始。イヤホンを推奨する案内を出す |
| **`lang` を設定し忘れる** | `<html lang="ja">` を拾って**日本語として認識される**。エラーは出ないので気づけない | 認識開始の直前に毎回代入する |
| **無音8秒で勝手に終了する** | エラーが出て初心者が驚く | `no-speech` はエラー扱いせず、普通の画面に戻す。残り秒数を画面に出す |
| **自動で再起動させると無限ループになる** | 権限拒否時に3ミリ秒周期でループしてタブが固まる | **連続認識と自動再起動の機能ごと採用しない**。構造的に起きないようにした |
| **読み上げの声の一覧が最初は空** | 起動直後に読み上げると無音 | 一覧取得を3重待ち(同期取得 → イベント待ち → ポーリング → 3秒で打ち切り) |
| **読み上げが15秒前後で勝手に止まる** | 長文の途中で切れる | 1発話180文字以内に分割。加えてタイマーで見張り、応答がなければ先へ進める |
| **停止ボタンを押すたびにエラーが出る** | 正常な中断がエラー表示される | 自分で止めた場合の中断イベントは握り潰す |
| **`stop()` と `abort()` を取り違える** | 「話し終わり」を押すと**認識結果が丸ごと消える** | 話し終わりは必ず `stop()`。`abort()` は破棄用 |
| **タイマーの止め忘れ** | 画面を離れても裏で喋り続ける | タイマーIDを全部配列で保持し、画面破棄時に一括解除 |

**要するに**: このアプリのコードで一番慎重に扱うべきは `js/05-speech.js` と `js/06-session.js` の2つです。ここを触るときは [../app/README.md](../app/README.md) の注意書きを必ず読んでください。

## 7. プライバシーと運営上の注意

技術以前に、部として決めておくべきことがあります。

### 7-1. 部員の声が Google に送られることを明示する

前述のとおり、Chrome の音声認識は音声を Google のサーバーへ送信します。**これは無料であることの裏返しのコスト**です。アプリでは初回起動時に同意画面を出し、README にも明記しました。部としても、勧誘時に口頭で伝えてください。

なお、録音データがアプリ側に保存されることはなく、学習記録はその端末の中だけに残ります。

### 7-2. 共有パソコンでは記録が混ざる

新歓ブースの共有 PC で使うと、全員の記録が1つに混ざります。**URL の末尾に `?demo=1` を付けると記録を一切保存しない体験モード**で起動するので、共有 PC ではこの URL をブックマークしてください。

### 7-3. 点数でランキングを作らない

点数の差はマイクの品質や周囲の騒がしさで簡単に十数点動きます。この数字で部員に序列をつけると、**一番練習が必要な初級者から順に離脱します**。アプリ側でも点数表示は既定でオフ、ランキング機能は恒久的に作らない方針にしました。競わせるなら「発話回数」など努力量ベースにしてください。

**要するに**: 音声が外部に送られること、共有 PC では `?demo=1` を使うこと、点数で競わせないことの3点を、部の運用ルールとして決めておいてください。

## 8. 実装したもの

[../app/](../app/) に実装済みです。詳しい使い方と保守方法は [../app/README.md](../app/README.md) にあります。

### 8-1. 機能

- **リピート練習**: お手本を聞く → 声に出す → 単語ごとに「伝わったか」を色と記号で表示
- **6カテゴリ36フレーズ**: 自己紹介 / キャンパスで / 学食・カフェで / 留学生と話す / サークル紹介(新歓) / 旅行で
- **通じにくい語ランキング**: 何度やっても伝わらない語と、代わりに何と聞き取られたかを集計
- **自作フレーズの追加**: `英文 | 和訳` を貼り付けるだけで教材が増える。JS を書けない部員でも追加できます
- **診断画面**: 動かないときの原因を切り分け、結果をコピーして相談できます
- **体験モード**(`?demo=1`): 記録を保存しない共有 PC 用

### 8-2. 構成

ビルドツール・パッケージマネージャ・外部ライブラリ・外部フォントを**一切使っていません**。`npm install` は不要で、ファイルを置くだけで動きます。

```
app/
├── index.html          エントリ
├── README.md           使い方と保守手順
├── css/                デザイントークンとレイアウト
├── data/decks.js       ★教材データ。部員が編集するのはここ
├── js/                 11ファイル。依存の向きは一方向
└── test/test.html      ダブルクリックで開けるテスト
```

教材を足したら `test/test.html` をダブルクリックしてください。id の重複や文末の記号忘れがその場で分かります。

**要するに**: 部員が触るのは `data/decks.js` かアプリ内の貼り付け画面だけです。それ以外を触るときは [../app/README.md](../app/README.md) の「慎重に触る場所」を読んでください。

## 9. 要確認事項

今回の調査で裏が取れなかった項目です。実際に使い始める前に確認してください。

- **パソコン版 Edge での動作**。Chromium ベースなので動く可能性が高いが未検証。本アプリは現状「非対応」として扱っている
- **通常起動の Chrome が `file://` でマイク権限のダイアログを出すか**。ヘッドレス環境での計測しかできていない
- **1回の認識セッションに60秒の上限があるか**。Chromium 開発者の古い発言が根拠で、現行版での再確認ができていない
- **学内 Wi-Fi で Google の音声認識サーバーへ到達できるか**。大学のネットワーク構成次第なので、部室での実機確認が必要
- **iPhone / iPad の Safari で実用に耐えるか**。不具合報告が多い。本アプリは塞がず「動作が不安定なことがあります」の警告帯を出したうえで使わせる方針にしている(§7 参照)。実機での連続利用は未検証
- **Android の Chrome で通しで練習できるか**。動作報告はあるが、実機での連続利用は未検証
- **Chrome の仕様変更に追随できるか**。読み上げ機能は Chrome 130 前後で不安定になった事例がある。同種の変更が起きたら診断画面の出力を添えて報告してください

**これらは実機で確かめるのが最も確実です。** 部室のパソコンと部員のスマホで、実際に1カテゴリ通しで練習してみてください。
